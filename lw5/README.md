# Лабораторная работа 5

## Байесовская сеть для AI-ассистента платформы онлайн-бронирования отелей

Тема диплома: «Исследование и разработка AI-ассистента для личного кабинета платформы онлайн-бронирования отелей».

**Цель работы:** определить байесовскую сеть для оценки вероятности успешного бронирования и возможной ошибки настройки, реализовать вероятностный вывод на Prolog и проверить вычисления на тестовых примерах.

**Задание:**

1. Определить байесовскую сеть своей предметной области, содержащую не менее пяти переменных — пункт № 3.
2. Реализовать обработку сети и предложить не менее трех тестов вычисления вероятностей событий — пункт № 7.

В работе используются шесть переменных, пять основных расчетных сценариев и автоматические тесты. Все численные параметры — учебные допущения автора модели, а не статистика реальной платформы. Модель не подключается к личному кабинету и не изменяет его настройки.

## 1 Определение байесовской сети

### 1.1 Предметная область

AI-ассистент помогает сотруднику отеля анализировать проблемы онлайн-бронирования. Детерминированная экспертная система проверяет известные факты и правила. Байесовская сеть дополняет такой подход: она позволяет оценивать вероятности, когда часть обстоятельств неизвестна.

Единица наблюдения — одна попытка бронирования выбранного тарифа на определенные даты. Успех означает завершение именно этой попытки. Переход на другой тариф или другие даты считается новым случаем. Обращение за помощью относится к этой же попытке и может произойти как после успеха, так и после неудачи.

### 1.2 Переменные

Каждая переменная принимает два значения: `yes` — событие произошло, `no` — событие не произошло.

| Обозначение | Имя в Prolog | Значение состояния yes |
|---|---|---|
| H | `high_demand` | Для выбранного периода наблюдается высокий спрос |
| E | `config_error` | В настройках тарифа имеется ошибка, способная повлиять на показ |
| R | `rooms_available` | Для запроса есть подходящий номер на весь период проживания |
| V | `rate_visible` | Тариф показывается гостю в рассматриваемом интерфейсе |
| B | `booking_success` | Попытка бронирования успешно завершена |
| S | `help_request` | По этой попытке возникло обращение за помощью |

Видимость тарифа и наличие номера в модели проверяются отдельно: показ предложения еще не означает, что оно доступно для завершения бронирования на выбранные даты. Ошибка настройки не обязательно полностью блокирует показ. Переменная E описывает один класс проблем, а не все возможные причины сбоя.

### 1.3 Структура сети

Сеть представляет собой ориентированный ациклический граф:

```text
high_demand                  config_error
     |                            |
     v                            v
rooms_available              rate_visible
     |                            |
     +------> booking_success <---+
                     |
                     v
                help_request
```

Ребра графа: `H → R`, `E → V`, `R → B`, `V → B`, `B → S`.

Высокий спрос влияет на вероятность наличия свободных номеров. Ошибка настройки влияет на показ тарифа. Успешное бронирование зависит от наличия номера и видимости тарифа. Исход попытки влияет на вероятность обращения за помощью.

Предполагается, что H и E независимы. Для R достаточно знать H, для V — E, для B — R и V, для S — B. Это упрощения модели: например, в реальных данных обращения могут зависеть и от других факторов. Условная вероятность, рассчитанная по сети, сама по себе не доказывает причину конкретной неудачи.

### 1.4 Таблицы вероятностей

Априорные вероятности корневых переменных:

| Переменная | P(yes) | P(no) |
|---|---:|---:|
| H | 0,30 | 0,70 |
| E | 0,10 | 0,90 |

Наличие номера зависит от спроса:

| H | P(R=yes при H) | P(R=no при H) |
|---|---:|---:|
| yes | 0,40 | 0,60 |
| no | 0,90 | 0,10 |

Видимость тарифа зависит от ошибки настройки:

| E | P(V=yes при E) | P(V=no при E) |
|---|---:|---:|
| yes | 0,20 | 0,80 |
| no | 0,98 | 0,02 |

Вероятность успешного бронирования:

| R | V | P(B=yes при R,V) | P(B=no при R,V) |
|---|---|---:|---:|
| yes | yes | 0,85 | 0,15 |
| yes | no | 0,00 | 1,00 |
| no | yes | 0,00 | 1,00 |
| no | no | 0,00 | 1,00 |

В выбранной модели бронирование невозможно без номера или без показа тарифа. Даже при наличии обоих условий остается вероятность незавершенной попытки — например, гость может отказаться от оформления. Отдельные причины такого исхода не моделируются.

Вероятность обращения за помощью:

| B | P(S=yes при B) | P(S=no при B) |
|---|---:|---:|
| yes | 0,05 | 0,95 |
| no | 0,60 | 0,40 |

Сумма вероятностей состояний `yes` и `no` в каждой строке равна единице. В коде хранится вероятность `yes`; вероятность `no` вычисляется как `1 − P(yes)`.

### 1.5 Факторизация совместного распределения

Совместная вероятность полного состояния определяется произведением:

```text
P(H,E,R,V,B,S) =
    P(H) × P(E) × P(R | H) × P(V | E) × P(B | R,V) × P(S | B).
```

Шесть двоичных переменных образуют `2^6 = 64` полных состояния. Для получения вероятности частичного события необходимо суммировать вероятности всех совместимых полных состояний.

## 2 Обработка сети на Prolog

### 2.1 Представление знаний

Файл `hotel_bayes.pl` содержит описание сети и механизм точного вывода.

```prolog
parents(booking_success, [rooms_available, rate_visible]).
cpt(booking_success, [yes, yes], 0.85).
```

Предикат `parents/2` задает родителей узла. Предикат `cpt/3` хранит вероятность состояния `yes` при заданных состояниях родителей. Порядок значений во втором аргументе `cpt/3` совпадает с порядком родителей.

### 2.2 Алгоритм вычисления

Используется точный вывод полным перебором, без случайной генерации выборки:

1. Проверить имена переменных и их значения в запросе и свидетельствах.
2. Перебрать полные состояния сети.
3. Для каждого состояния перемножить локальные вероятности согласно структуре графа.
4. Суммировать веса состояний, совместимых со свидетельствами.
5. Суммировать веса состояний, совместимых одновременно с запросом и свидетельствами.
6. Разделить вторую сумму на первую.

Формула условной вероятности:

```text
P(Q | O) = P(Q ∩ O) / P(O), если P(O) > 0,
```

где Q — запрашиваемое событие, O — наблюдаемые свидетельства. Суммы вычисляются по всем неизвестным переменным. Для небольшой сети перебор удобен и прозрачен; при увеличении числа переменных количество состояний растет экспоненциально. Для крупных сетей потребуется более эффективный алгоритм, например исключение переменных.

### 2.3 Интерфейс программы

| Предикат | Назначение |
|---|---|
| `probability(Query, Evidence, P)` | Вероятность события Query при свидетельствах Evidence |
| `marginal(Event, P)` | Безусловная вероятность одного события |
| `posterior(Variable, State, Evidence, P)` | Условная вероятность состояния одной переменной |
| `joint(World, P)` | Вероятность полного состояния из шести переменных |
| `demo` | Вывод результатов пяти основных сценариев |

`Query` и `Evidence` — списки пар вида `переменная-значение`. Несколько пар означают логическое И. Например, `[booking_success-yes, help_request-yes]` означает совместное наступление двух событий.

Пустой список свидетельств `[]` означает отсутствие наблюдений. Неизвестную переменную следует пропустить: отдельного состояния `unknown` в этой двоичной сети нет. Пустой запрос означает достоверное событие и имеет вероятность 1 при допустимых свидетельствах.

Повторные переменные внутри одного списка, недопустимые значения и неизвестные имена отклоняются. Если запрос противоречит допустимому свидетельству, результат равен 0. Если сами свидетельства имеют нулевую вероятность, программа сообщает `impossible_evidence`, поскольку условная вероятность не определена.

## 3 Тесты вычисления вероятностей

В формулах ниже буква без отрицания означает состояние `yes`, знак `¬` — состояние `no`.

### Тест 1 Вероятность успешного бронирования без наблюдений

```prolog
?- marginal(booking_success-yes, P).
```

Сначала вычисляются вероятности наличия номера и показа тарифа:

```text
P(R) = 0,30 × 0,40 + 0,70 × 0,90 = 0,75.
P(V) = 0,10 × 0,20 + 0,90 × 0,98 = 0,902.
```

R и V независимы до получения свидетельств в этой сети. Успех возможен только при R=yes и V=yes:

```text
P(B) = 0,75 × 0,902 × 0,85 = 0,575025.
```

**Ожидаемый результат:** `P = 0.575025`, или **57,5025%**.

### Тест 2 Вероятность бронирования при высоком спросе

```prolog
?- posterior(booking_success, yes, [high_demand-yes], P).
```

Свидетельство H=yes меняет вероятность R, но не V:

```text
P(B | H) = 0,40 × 0,902 × 0,85 = 0,30668.
```

**Ожидаемый результат:** `P = 0.30668`, или **30,668%**. Снижение относительно первого теста связано с меньшей доступностью номеров при высоком спросе.

### Тест 3 Вероятность ошибки настройки после неудачи

```prolog
?- posterior(config_error, yes, [booking_success-no], P).
```

Используется обратное обновление вероятности по наблюдаемому результату:

```text
P(B | E) = 0,75 × 0,20 × 0,85 = 0,1275.
P(¬B | E) = 1 − 0,1275 = 0,8725.
P(¬B) = 1 − 0,575025 = 0,424975.
P(E | ¬B) = 0,10 × 0,8725 / 0,424975 ≈ 0,2053061945.
```

**Ожидаемый результат:** примерно **20,5306%**. Неуспешная попытка увеличивает оценку вероятности ошибки с исходных 10%, но не подтверждает ее однозначно.

### Тест 4 Вероятность ошибки при обращении за помощью

```prolog
?- posterior(config_error, yes, [help_request-yes], P).
```

```text
P(S) = 0,05 × 0,575025 + 0,60 × 0,424975 = 0,28373625.
P(S | E) = 0,05 × 0,1275 + 0,60 × 0,8725 = 0,529875.
P(E | S) = 0,10 × 0,529875 / 0,28373625 ≈ 0,1867491376.
```

**Ожидаемый результат:** примерно **18,6749%**. Расчет демонстрирует передачу свидетельства через несколько узлов сети.

### Тест 5 Вероятность бронирования при отсутствии номеров

```prolog
?- posterior(booking_success, yes, [rooms_available-no], P).
```

Во всех строках таблицы B с R=no вероятность успешного бронирования равна нулю.

**Ожидаемый результат:** `P = 0.0`, или **0%**.

### Автоматическая проверка

Файл `hotel_bayes_tests.pl` содержит 17 тестов. Помимо пяти основных сценариев проверяются совместное событие, сумма вероятностей противоположных состояний, наблюдаемое и противоречащее наблюдению события, пустой запрос, нормировка всех 64 состояний, полнота таблиц и некорректный ввод.

Численные результаты сравниваются с независимо рассчитанными значениями с допуском `10^−9`.

## 4 Запуск

Откройте терминал в папке `lw5`. Для основного способа запуска необходим SWI-Prolog.

Демонстрация пяти сценариев:

```powershell
swipl -q -s hotel_bayes.pl -g demo -t halt
```

Автоматические тесты:

```powershell
swipl -q -s hotel_bayes_tests.pl -g run_tests -t halt
```

Работа в интерактивной консоли SWI-Prolog:

```prolog
?- [hotel_bayes].
?- demo.
?- probability([booking_success-yes, help_request-yes], [], P).
% P ≈ 0.02875125.
?- posterior(booking_success, yes,
             [rooms_available-yes, rate_visible-yes], P).
% P ≈ 0.85.
```

Альтернативная проверка с Node.js и SWI-Prolog WebAssembly:

```powershell
npm.cmd install --prefix .runtime swipl-wasm@8.1.2 --cache .runtime/npm-cache --ignore-scripts --no-audit --no-fund
node --preserve-symlinks --preserve-symlinks-main verify.cjs
```
