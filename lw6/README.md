# Лабораторная работа 6

## База данных и экспертная система через фреймы

**Выбранный вариант:** 2 — сформировать базу данных и экспертную систему через фреймы, пункт № 10.

**Предметная область:** AI-ассистент личного кабинета платформы онлайн-бронирования отелей.

**Цель:** представить сведения о двух тарифах в виде фреймов, реализовать наследование и переопределение свойств, а также экспертные правила проверки возможности бронирования.

Реализация выполнена на SWI-Prolog. Все объекты, цены и настройки — учебные примеры. Программа работает локально. Наследование в работе относится к представлению знаний во фреймах.

## 1 Соответствие заданию

| Требование | Реализация |
|---|---|
| Выбрать один вариант | Вариант 2 — фреймы |
| Описать два объекта | `standard_rate` и `promo_rate` |
| Не менее двух заданных свойств | Пять собственных слотов у стандартного тарифа, шесть у промотарифа |
| Не менее двух наследуемых свойств | Четыре наследуемых слота у стандартного тарифа, три у промотарифа |
| Создать базу данных | Факты `frame/2`, `parent/2`, `slot/3` |
| Создать экспертную систему | Четыре правила, механизм вывода и объяснение оснований |

В базе имеются ровно два конкретных объекта. Общий фрейм `tariff` является прототипом, а не третьим объектом тарифа. Иерархия содержит два уровня: прототип и его экземпляры.

## 2 Структура фреймов

Фрейм — структура представления знаний об объекте. Его свойства называются слотами. Значение слота может быть задано непосредственно в объекте либо получено от родительского фрейма.

```text
Уровень 1                 tariff
                    общий фрейм прототип
                           /      \
                          /        \
Уровень 2       standard_rate    promo_rate
                объект 1         объект 2
```

Для обоих экземпляров отношение `parent/2` указывает прототип, из которого можно наследовать отсутствующие локальные значения. Используется одиночное наследование: у каждого объекта один родитель.

### 2.1 Общий фрейм

| Слот | Значение по умолчанию | Смысл |
|---|---|---|
| `currency` | `rub` | Валюта цены — рубль |
| `website_enabled` | `yes` | Официальный сайт включен как источник продаж |
| `payment_method` | `on_arrival` | Оплата при заселении |
| `min_nights` | `1` | Минимальная продолжительность — одна ночь |

```prolog
frame(tariff, prototype).
slot(tariff, currency, rub).
slot(tariff, website_enabled, yes).
slot(tariff, payment_method, on_arrival).
slot(tariff, min_nights, 1).
```

В рамках этой учебной модели значения прототипа считаются установленными общими настройками. Сведения о наличии номеров и активности заданы отдельно для каждого объекта.

### 2.2 Объект Стандартный тариф

| Слот | Эффективное значение | Способ получения |
|---|---|---|
| `name` | Стандартный тариф | Задано в объекте |
| `price` | `5000` | Задано в объекте |
| `active` | `yes` | Задано в объекте |
| `rooms_available` | `yes` | Задано в объекте |
| `meal` | `breakfast` | Задано в объекте |
| `currency` | `rub` | Унаследовано от `tariff` |
| `website_enabled` | `yes` | Унаследовано от `tariff` |
| `payment_method` | `on_arrival` | Унаследовано от `tariff` |
| `min_nights` | `1` | Унаследовано от `tariff` |

Объект содержит **5 заданных** и **4 наследуемых** свойства.

### 2.3 Объект Промотариф

| Слот | Эффективное значение | Способ получения |
|---|---|---|
| `name` | Промотариф | Задано в объекте |
| `price` | `4000` | Задано в объекте |
| `active` | `no` | Задано в объекте |
| `rooms_available` | `no` | Задано в объекте |
| `meal` | `none` | Задано в объекте |
| `min_nights` | `3` | Задано в объекте, переопределяет значение прототипа |
| `currency` | `rub` | Унаследовано от `tariff` |
| `website_enabled` | `yes` | Унаследовано от `tariff` |
| `payment_method` | `on_arrival` | Унаследовано от `tariff` |

Объект содержит **6 заданных** и **3 наследуемых** свойства. Значение `min_nights=3` относится к собственным данным: после переопределения значение `1` от прототипа не используется для этого объекта.

Цена указана за одну ночь в условной учебной модели; стоимость всего проживания программа не рассчитывает. Наличие номеров относится к одному заранее выбранному периоду. Для другой ситуации нужно актуализировать исходные факты. Питание и цена являются описательными слотами и не участвуют в диагностике.

## 3 Механизм наследования

Главный предикат доступа к свойству:

```prolog
get_slot(Frame, Slot, Value, Origin).
```

`Frame` и `Slot` должны быть заданы. `Value` — найденное значение, `Origin` — его происхождение: `own(Frame)` или `inherited(Parent)`.

Алгоритм:

1. Проверить существование фрейма и имени слота.
2. Найти локальное значение слота в текущем фрейме.
3. Если локального значения нет, перейти к родителю.
4. Вернуть первое найденное значение и фрейм, в котором оно задано.
5. Если определения нет во всей цепочке, завершить поиск неуспехом.

Собственное значение имеет приоритет над родительским. Выбор определения выполняется до сопоставления с запрошенным значением. Поэтому запрос `get_slot(promo_rate, min_nights, 1, _)` дает `false`, а не возвращает скрытое значение прототипа.

Поиск хранит посещенные фреймы, чтобы не зациклиться при ошибочном цикле в иерархии. База статическая: локальные значения уникальны, добавление данных во время консультации не предусмотрено.

## 4 Экспертная система

Экспертные правила работают с эффективными значениями слотов, полученными через `get_slot/4`. Следовательно, вывод учитывает и собственные, и наследуемые данные.

| Правило | Условие | Заключение и рекомендация |
|---|---|---|
| r01 | `active=no` | Тариф неактивен; проверить необходимость активации |
| r02 | `rooms_available=no` | Номеров нет; проверить даты и наличие |
| r03 | `website_enabled=no` | Сайт выключен как источник продаж; проверить настройку |
| r04 | Число ночей меньше `min_nights` | Срок проживания не соответствует минимуму; уточнить даты или условия |

Закрытие продаж может быть намеренным, поэтому рекомендации не требуют автоматически менять настройки. Ни одно изменение в личном кабинете не выполняется.

Консультация запускается предикатом:

```prolog
consult_tariff(Object, Nights, report(Status, Findings, Missing)).
```

`Object` — имя конкретного объекта; `Nights` — положительное целое число ночей. Программа проверяет все правила и собирает все сработавшие заключения.

Возможные статусы:

- `blocked` — обнаружено хотя бы одно препятствие по правилам модели;
- `insufficient_data` — препятствий пока не найдено, но отсутствует обязательное свойство;
- `no_known_blockers` — все необходимые свойства доступны и известные препятствия не найдены.

`Findings` содержит идентификатор правила, рекомендацию и подтверждающие значения с указанием их происхождения. `Missing` перечисляет неизвестные обязательные слоты. Отсутствие значения не считается значением `no`.

Статус `no_known_blockers` относится только к четырем реализованным проверкам и не гарантирует успешного бронирования в реальной системе. В текущих двух объектах все обязательные слоты заполнены; ветвь недостатка данных предусмотрена для расширения базы.

## 5 Примеры запросов

### Пример 1 Заданное свойство

```prolog
?- get_slot(standard_rate, price, Value, Origin).
Value = 5000,
Origin = own(standard_rate).
```

### Пример 2 Наследуемое свойство

```prolog
?- get_slot(promo_rate, currency, Value, Origin).
Value = rub,
Origin = inherited(tariff).
```

### Пример 3 Переопределение

```prolog
?- get_slot(promo_rate, min_nights, Value, Origin).
Value = 3,
Origin = own(promo_rate).

?- get_slot(standard_rate, min_nights, Value, Origin).
Value = 1,
Origin = inherited(tariff).

?- get_slot(promo_rate, min_nights, 1, _).
false.
```

Переопределение в промотарифе не меняет общий фрейм и свойства стандартного тарифа.

### Пример 4 Консультация по стандартному тарифу

```prolog
?- consult_tariff(standard_rate, 2, Report).
Report = report(no_known_blockers, [], []).
```

Тариф активен, номера есть, сайт включен, две ночи удовлетворяют наследуемому минимуму в одну ночь.

### Пример 5 Консультация по промотарифу

```prolog
?- consult_tariff(promo_rate, 2, Report).
```

Ожидается `blocked` и три заключения: **r01, r02, r04**. Тариф неактивен, номеров нет, а две ночи меньше собственного минимума в три ночи. Объяснение r04 содержит:

```prolog
stay_evidence(2, 3, own(promo_rate))
```

Для запроса на три ночи r04 уже не срабатывает, но r01 и r02 сохраняются. Изменение одного условия не устраняет другие препятствия.

## 6 Состав файлов и запуск

| Файл | Назначение |
|---|---|
| `hotel_frames.pl` | Фреймовая база данных, наследование и экспертные правила |
| `hotel_frames_tests.pl` | Автоматические тесты |
| `verify.cjs` | Необязательная проверка через Node.js и SWI-Prolog WebAssembly |
| `README.md` | Описание лабораторной работы |

Откройте терминал в папке `lw6`. Для основного запуска необходим SWI-Prolog.

Вывод двух фреймов и результатов консультаций:

```powershell
swipl -q -s hotel_frames.pl -g demo -t halt
```

Запуск тестов:

```powershell
swipl -q -s hotel_frames_tests.pl -g run_tests -t halt
```

В интерактивной консоли SWI-Prolog:

```prolog
?- [hotel_frames].
?- demo.
?- describe(standard_rate, Properties).
?- consult_tariff(promo_rate, 3, Report).
```

Альтернативная проверка при наличии Node.js:

```powershell
npm.cmd install --prefix .runtime swipl-wasm@8.1.2 --cache .runtime/npm-cache --ignore-scripts --no-audit --no-fund
node --preserve-symlinks --preserve-symlinks-main verify.cjs
```

## 7 Проверка и вывод

Подготовлены 22 теста. Они проверяют количество объектов и уровней, наличие необходимого числа собственных и наследуемых свойств, приоритет переопределений, независимость объектов, результаты консультаций, граничное число ночей, объяснения и обработку некорректных запросов.

Разработана фреймовая база данных с двумя конкретными объектами и общим прототипом. Реализованы поиск свойств, наследование и переопределение значений. Экспертная система использует полученные свойства для диагностики и указывает основания каждого сработавшего правила.
